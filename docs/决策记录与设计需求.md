## 0. 给 Codex 的一句话

做一个**高效率的批量套图生产台**：一个人一天要处理约 100 个商品，每个商品一套 8 张主副图。界面要紧凑、有设计感、像专业生产工具，而不是展示网站；核心是「不停地上传下一个商品，同时让已经在跑的套图自己往前走，只有需要人判断的地方才打断人」。

你只负责前端：概念图 → 用户确认 → 实现。后端接口已经准备好（第 7 节），**不要改 `imggen/` 下的生成、提示词、校验和调度逻辑，不要调用真实 OpenAI API**。

## 1. 项目是什么

- 输入：一个美妆商品的产品图（1–4 张，不同角度）。
- 输出：一套 8 张 1:1 英文主副图（Temu 美区上架用），附自动检查结果、费用记录；通过的图自动存进成品文件夹。
- 运行：用户 Mac 本机，`python app.py`，浏览器打开 `http://127.0.0.1:8765`。只有一个用户，没有登录。
- 出图：OpenAI 官方 API，`gpt-image-2.5-flare`，medium，1024×1024，实测约 $0.026/张，25–55 秒/张。

8 个图位（`imggen/templates/slots.yaml`）：

| 图位 | 名称 | 有字吗 | 说明 |
|---|---|---|---|
| 01 | 首图 | 无 | 商品居中，约占 65% |
| 02 | 卖点图 | 有 | 商品在右，标题和要点在左 |
| 03 | 成分图 | 有 | 标题在上，成分名在各自道具旁 |
| 04 | 质地特写 | 有 | 质地在前，说明放在空白处 |
| 05 | 使用方法 | 有 | 三格竖图拼成，每格有 STEP 标签和说明；缺用法时跳过 |
| 06 | 场景图 | 有 | 手拿商品；面膜类可出完整人脸 |
| 07 | 尺寸图 | 有 | 白底，容量一行；没有容量时跳过 |
| 08 | 礼品场景 | 无 | |

一套约 10 次出图调用（7 张单图 + 使用方法 3 格），按 30% 重出约 13 次，**约 $0.35/套**（含识别标签、做计划的文本调用）。

## 2. 时间线与前因后果（按时间顺序，过程要知道）

1. **2025 起点 → 2026-11 重启。** 目标从「做几张图」变成「批量生产工具」。只用 OpenAI 官方 API，不用中转站。
2. **11/11 两轮实测（Playground，38 张，$1.055595）。** 结论：默认 2.5-flare medium；新增英文文字模型拼写 7/7 正确；包装上的原文小字模型会重绘出错 → 提示词里写入「标签原文块」+ 出图后「原标签回贴」；多格图一次生成会乱码 → 使用方法每格单独生成；出现过盒子丢失、多出产品 → 需要件数检查。
3. **11/12 第三轮：原标签回贴离线复核（$0）。** GPT 逐张放大挑出 24/26 张有瑕疵；用户判断多为放大才可见的小瑕疵。定下：不再无限复核；硬问题（大字错、重影、丢件）拦截，小瑕疵只提示由人决定；回贴变差则自动放弃回贴。
4. **11/13–11/22 Claude/Codex 开发到 v1.4.2。** 本机工作台跑通：导入 → 识别标签 → 人工确认 → 计划 → 出图 → 审核 → ZIP 导出；后台保存密钥；商品资料提炼卖点；不同图位可并行重出。
5. **Codex 的界面探索（11/19–11/23）。** 做过：浅色工作台、深色背景版、带视频动效的展示首页、三栏同屏、校样台、大图胶片带、扫光动效、多套结构方案、第四轮「连续校样 / 工序折叠 / 清单校样 / 双页交接」。用户**认可的方向**：四个阶段「资料 → 构图 → 校样 → 成品」；校样用**同一个画框 + 一条竖线左右拖动**对比前后版本；通过后直接接下一张。用户**否定的**：视觉越改越难看、无效留白、多个方案太乱、页面割裂（产品库/计划/审核/导出分开跳转）、动效不够有表现力却又分散注意力。
6. **11/23 交接给 Claude 做统筹规划。** 确认四阶段工作流和分期；用户确认的 8 条决定见第 3 节。
7. **11/24 v1.5.0：** 照片永不覆盖、任务记录不怕重启、进度按完成顺序走、审核卡片原位更新、文本模型费用计入预算。
8. **11/24 用户改决定：文字不由程序加底条，而由图像模型直接设计进画面**（所有正式主图都是文字自然设计在图上的）。v1.6.0 实现：提示词逐条列出已确认文字 + 规定词组不能被拆开；去掉底条和「重新排版」；使用方法三联图的 STEP 和说明也由模型画；出图后 OCR 核对拼写和断行。
9. **11/24 确认账号 Launch 档：gpt-image 系列共用每分钟 150 张（IPM）。** 定下：整套最多用 80%（120/分钟），30/分钟留给单张重出；最多同时 10 套，其余排队；单张重出走优先通道。
10. **11/24 用户看了现在的后台：太割裂，不像自动化批量智能平台。** 决定：前端交给 Codex 按本文重新设计；Claude 提供后端接口（v1.7.0）和本文；以 GitHub `main` 为唯一基线，不管以前未提交的版本。

## 3. 现行决定（一律按现在的来）

| # | 决定 | 对界面的含义 |
|---|---|---|
| D1 | 文字由图像模型设计进画面；程序只规定「用哪些字」和「哪些词组不能拆开」，位置按现有图位设定 | 界面里**没有**排版编辑器、文字层、拖文字框 |
| D2 | 构图第一阶段全自动 | 「构图」阶段**不需要用户操作**，只展示状态；以后接模板库 |
| D3 | 只有回贴检查通过才默认用回贴版；校样默认突出「包装原图 vs 当前图」 | 校样画框的对比对象可切换：上一版 / 包装原图 / 生成版↔回贴版 |
| D4 | 同一图位的历史版本全部保留；最新通过的是当前版 | 校样要能翻历史版本；成品文件夹里旧版本也在 |
| D5 | 商品资料只支持文字：粘贴、txt、md、csv、docx；不读 PDF 和图片 | 资料区只有这些入口 |
| D6 | 缺资料的图位直接跳过并说明原因 | 跳过的图位显示为灰色 + 原因，不算未完成 |
| D7 | 识别标签、做计划等文本调用也计入每日预算 | 顶部费用条包含它们 |
| D8 | 缩略图可读性阈值：测试后再定 | 暂不做相关 UI |
| D9 | 改字 = 单张重出（约 $0.026），不做「不花钱重排」 | 重出前可以改这张的文字（只能选已确认的文字），按钮上写清费用 |
| D10 | **每个商品都必须人工确认标签**，不自动确认 | 「待确认标签」是人必须处理的队列，要放在最显眼处 |
| D11 | 上传方式：一个一个商品上传；拖入、选文件、**粘贴图片（⌘V）**；确认后开始生成，**不等上一套**，马上传下一个 | 上传区永远在手边，不被其他面板挡住 |
| D12 | 通过即归档到 `workspace/成品/日期/商品/`，不需要 ZIP | 「成品」是自动结果；ZIP/ERP 表降为次要入口 |
| D13 | 最多同时 10 套，其余排队；单张重出优先 | 顶部显示「生成中 n 套 / 排队 m 套 / 每分钟已用 x/150 张」 |
| D14 | 日常界面隐藏 GPT、提示词、模型名、token 等技术信息 | 需要时放在「详情」折叠里 |

## 4. 明确排除（这一版不要做，不要考虑）

- 程序在图片上加文字底条、文字层、可拖动文字框、字体选择。（D1）
- 手动拖框构图。模板库以后做，现在只在界面上**预留一个「模板」位置**即可，不做功能。
- 自动确认标签。（D10）
- 读取 PDF / 图片里的文字作为商品资料。（D5）
- 多用户、登录、权限、云端部署、自动上架、店铺数据。
- 展示型首页、视频背景、扫光、悬停播放、营销式大标题和大面积留白。原展示页保留在 `/showcase`，不要再动它。
- 深色主题作为主界面（用户觉得难看）；多个并列方案（用户觉得乱）。
- 修改 `imggen/` 后端逻辑、提示词、`slots.yaml`、调度、费用计算；调用真实 OpenAI API。需要新接口时写在交付说明里，由 Claude 加。

## 5. 用户与使用节奏（设计必须围绕这个）

- 一个人，8 小时，目标约 100 套/天（80–120）。机器不是瓶颈：API 理论上 5 小时能跑约 2,700 套；**瓶颈是人**：每套约 4 分钟人工（上传 + 逐行确认标签约 1.5–2 分钟，校样 8 张约 1.5–2 分钟，偶尔改字重出）。
- 所以界面的目标是**把人每套的 4 分钟压缩到最短**：少跳页、少点击、键盘优先、自动推进到「下一个需要我」的地方。
- 典型一小时：连续上传 5–10 个商品 → 每个识别完就确认标签并开始 → 期间前面的套陆续出完 → 插空校样、通过、个别重出 → 通过的自动进成品。

## 6. 体验流程（Claude 定，Codex 照此设计）

### 6.1 四个阶段与每个商品的状态

```
资料 ──────────────► 构图 ─────────► 校样 ──────────► 成品
上传 → 识别标签 → 确认标签     自动（排队/生成中）   逐张通过/重出      自动归档
 new   reading     confirm      ready/queued/generating   proof              done
```

后端状态（`/api/board` 的 `stage`）：`new` 待识别 · `reading` 识别中 · `confirm` 待确认标签 · `ready` 待开始 · `queued` 排队中 · `generating` 生成中 · `proof` 待校样 · `done` 已完成（另有 `error`）。

**需要人的只有两个：`confirm`（确认标签）和 `proof`（校样）。** 其余都是机器在跑，只显示进度。

### 6.2 单页结构（一个页面完成全部工作，不跳页）

建议布局（1440×900 为主，1280 宽也要能用）：

1. **顶栏（一行）**：产品名 · 产能条（生成中 n 套 / 排队 m 套 / 每分钟已用 x/150 张）· 今日费用 $x / 预算 $y · 设置入口。
2. **左栏：上传 + 我的待办**（窄，常驻）
   - 上传区：拖入 / 点击选图 / ⌘V 粘贴，**一次 = 一个商品**（几张图算同一商品不同角度），可顺手改商品名。上传后立刻清空，可以传下一个。
   - 「需要我处理」列表：先 `confirm`，再 `proof`，按时间排；每项一个缩略图 + 名称 + 一个动作词（确认标签 / 校样 3 张）。
3. **中间：生产板**（主体，紧凑行而不是大卡片）
   - 每个商品一行：缩略图、名称、阶段标签、**8 个图位的迷你缩略图条**（空 → 排队 → 生成中 → 有图 → 有提示 → 已通过 → 跳过，各有清楚状态），进度、费用。
   - 顶部按阶段筛选（带数量），默认「全部进行中」；已完成的折叠到底部或「成品」筛选里。
   - 行实时更新（轮询 `/api/board`，1.5–3 秒），出一张亮一张，不刷新页面、不打断正在做的事。
4. **右侧：焦点面板**（选中一个商品时出现；内容随阶段变）
   - `confirm` → **标签确认**：左边包装原图（可放大），右边逐行文字（两路识别不一致的行高亮）、大字勾选、卖点勾选、容量/件数/成分/用法等字段；底部主按钮「确认并开始生成（约 $0.35）」，快捷键 ⌘Enter。确认后自动跳到下一个 `confirm`。
   - `queued`/`generating` → 只显示 8 个图位的进度和预计时间，不需要操作。
   - `proof` → **校样台**：大画框 + 竖线滑杆对比（默认「包装原图 vs 当前」，可切「上一版 vs 当前」「生成版 vs 回贴版」）；下方 8 图位胶片条；自动检查提示（拼写/断行/大字/回贴）直接标在当前图旁；操作：通过（A）、重出（R，展开一个小编辑框：可调整这张的文字（只能用已确认的文字）+ 一句说明，按钮写「重出这张 约 $0.026」）、切换生成版/回贴版（L）、←/→ 切图位；**通过后自动跳下一张待校样**，一套全部通过后自动跳下一个商品。
   - `done` → 成品：8 张缩略图、归档文件夹路径、「打开文件夹」「导出 ERP 表 / ZIP（可选）」。
5. **资料（商品文案）**：在标签确认面板里作为一个折叠区：粘贴文字或选 txt/md/csv/docx → 提炼卖点 → 看原文依据 → 勾选采用。（已有后端：见 7.3）

### 6.3 键盘

| 键 | 作用 |
|---|---|
| ⌘V | 粘贴图片 = 新建一个商品 |
| ⌘Enter | 确认标签并开始生成 |
| A / R / L | 通过 / 重出 / 切换生成版与回贴版 |
| ← → | 上一个/下一个图位 |
| J / K | 下一个/上一个需要我处理的商品 |
| 空格按住 | 校样画框临时显示包装原图 |
| Esc | 关闭焦点面板 |

### 6.4 必须设计的状态与异常

空状态（还没有商品）、识别中、识别失败（可重试）、确认表单有警告（某卖点含禁用词/数字）、排队中（显示前面还有几套）、限流自动放慢、今日预算快用完/已用完（停止新任务的明确提示）、某张检查有提示、某张生成失败（原位显示原因 + 重试）、工具重启后任务「中断」（可再次开始，只补没出的图）、旧版带底条的图（`legacy_strip: true`，提示「旧版样式，建议重出」）。

### 6.5 视觉方向

- 专业生产工具：紧凑、信息密度高、对齐严格；浅色中性底 + 一个强调色；状态色克制（成功/提示/错误）。
- **图片是主角**，界面框架退后；不用大面积留白、不用营销式大字、不用背景视频和装饰动效。
- 动效只用于状态变化（出图完成时缩略图淡入、进度推进、通过后切到下一张），短而明确。
- 字号：正文 13–14px，辅助 12px；数字用等宽数字。中文界面，商品文字原样显示英文。
- 参考气质：Linear / Figma / 专业照片筛选工具（Lightroom 选片）的密度与效率。

## 7. 后端现状与接口（v1.7.0，Codex 直接用）

页面服务端拼 HTML 也可以，用 JSON 接口写前端也可以；新工作台建议用纯前端（原生 JS，不引入构建工具）调用下面的接口。

### 7.1 总览

`GET /api/board` →

```json
{"products": [{"id": "3-咖啡磨砂膏", "name": "3.咖啡磨砂膏", "thumb": "/files/...",
   "stage": "proof", "stage_label": "待校样", "progress": {"done": 4, "total": 7} ,
   "variants": [{"variant": "A", "slots": 7, "made": 7, "approved": 3, "flagged": 1}],
   "jobs": [{"id": "ab12cd34", "kind": "生成套图", "done": 4, "total": 7, "phase": "running"}],
   "last_error": "", "archived_to": "/.../workspace/成品/2026-11-24/3-咖啡磨砂膏"}],
 "counts": {"new": 0, "reading": 0, "confirm": 1, "ready": 0, "queued": 2, "generating": 3, "proof": 4, "done": 9, "error": 0},
 "stages": {"new": "待识别", "...": "..."},
 "capacity": {"images_per_minute": 150, "use_ratio": 0.8, "max_parallel_sets": 10,
   "running_sets": 3, "queued_sets": 2, "images_last_minute": 38,
   "budget_usd_per_day": 50, "spent_today_usd": 12.4, "est_usd_per_image": 0.026}}
```

### 7.2 单个商品

`GET /api/sku/{id}` → `sources`（包装原图 URL 列表）、`label_draft`（机器识别结果，含 `lines[].ocr_sim/ocr_found` 用于高亮）、`label`（已确认）、`product_copy`（资料提炼草稿）、`variants.A.slots[]`：`slot, name, skip, skip_reason, copy[{role,text}], status(empty/pending/redo/approved), busy, busy_phase, current{n,file,which,flags,version}, versions[{n,generated,pasted,flags,error,legacy_strip,added_text,sec}]`、`row`（同 board 一行）。

### 7.3 动作

| 动作 | 接口 |
|---|---|
| 上传一个商品（拖入/选择/粘贴） | `POST /api/intake`，multipart：`files`（1–n 张图），可选 `name`；会自动开始识别标签 → `{sku, job_id}` |
| 重新识别 | `POST /api/sku/{id}/read-label` |
| 确认标签并开始 | `POST /api/sku/{id}/confirm`，JSON：与 `label.json` 同字段（`lines[{text,size}]`、`product_name`、`capacity`、`pieces`、`pieces_text`、`category`、`key_ingredient`、`ingredient_names[]`、`allowed_claims[]`、`texture`、`texture_caption`、`scene_caption`、`usage_steps[]`）+ `"start": true` → `{ok, warnings[], job_id}` |
| 开始/继续一套 | `POST /api/sku/{id}/start` `{"variant":"A"}` |
| 改某张的文字（重出前） | `POST /api/sku/{id}/slot-copy` `{"variant","slot","headline"?, "bullets"?, "ingredient_labels"?, "texture_caption"?, "scene_caption"?, "capacity"?, "steps"?[captions]}`；只接受已确认的文字，否则 400 + 原因 |
| 通过 / 重出 / 切换版本 | `POST /api/review` `{"sku","variant","slot","action":"approve"|"redo"|"toggle","note"?}`；通过时自动归档；重出返回 `job_id` |
| 整套通过 | `POST /api/review_all` `{"sku","variant"}` |
| 任务列表 | `GET /api/jobs?sku=`（`state`: running/done/error/interrupted，`phase`: queued/running） |
| 某个图位变了没 | `GET /api/slot_versions?sku=` → `{"A:3": "版本键"}` |
| 商品资料提炼（旧页面接口，表单） | `POST /sku/{id}/product-copy`（`source` 文本）→ 后台任务；`POST /sku/{id}/product-copy/apply`（勾选采用）。需要 JSON 版时告诉 Claude |
