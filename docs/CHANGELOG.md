## 2026-11-11 · v0.1 原标签回贴原型

**做了什么**
- `imggen/repair/label_paste.py`：把产品原图上的标签像素贴回 AI 生成图。
  - 不依赖抠图模型（BiRefNet 在 8GB 内存上跑不动，ISNet 抠生成图效果差），改用 SIFT 特征匹配 + 多平面单应性（盒子正面、瓶身各一个面）。
  - 整个产品面按就近原则分给各个面，避免接缝穿过文字造成"重影"。
  - 逐块校验原图和生成图是否对得上：生成图里不存在的部分（比如被模型画丢的盒子）不会被硬贴上去。
  - 遮挡保护：手指、滴管等大块遮挡保留生成图的像素。
  - 贴不了的（覆盖率 < 35% 或没有可靠的面）返回原生成图，并标为失败 → 交给重出。
- `imggen/qa/label_text.py`：本地 OCR（rapidocr）识别标签文字并与确认文字比对。
- `app.py`：本地网页，审核回贴结果。
- 测试：`tests/test_label_paste.py`（合成图：模型"改正"了错字 → 回贴后恢复原文）。

**在 11/11 GPT 测试的 26 张图上的结果**
- 24 张成功贴回，每张约 1.5 秒（CPU）。ZYZT 的 "Replenis h" 回贴后恢复为原文，无重影。
- 2 张判为失败：T2_A、T6_A_2，这两张图里的盒子都被模型画丢了。判断正确，应当重出而不是硬贴。
- 已知局限：贴回后瓶身上模型画的水珠、反光会被原图的干净标签替换；多格小图里的小瓶子分辨率低，贴回后字仍小；个别图（T6_A_6）盒子边缘有几像素错位，出现细微双边。
- 修正：产品边缘漏出原图白底的小白块（遮挡检测阈值调低后消除）。

**发现**
- 本地 OCR 噪声大：在产品原图上也会吞空格、把 O 读成 0，区分不了 "Replenis h" 和 "Replenish" 这种一个空格的差别。
  → 结论：本地 OCR 只用来查明显错误（整行缺失、乱码）；包装文字的保证靠"能贴就贴"。配置项 `repair.label_paste_always: true`。
  → 细微差别的文字核对改用 OpenAI 视觉模型（带确认文字做对照），在开发 F5 时接入。
